## Ведение DESIGN.md и Git

После выполнения ЛЮБОЙ задачи, которая добавляет, изменяет или удаляет игровую механику, систему или архитектурное решение, ты ОБЯЗАНА:
1. Прочитать текущий res://DESIGN.md перед началом изменений — это источник истины о состоянии проекта.
2. После завершения задачи — обновить соответствующий раздел DESIGN.md: перемещать реализованные фичи из TODO/roadmap в статус "✅ Реализован" с кратким описанием финальных параметров, добавлять новые технические уроки/баги в соответствующий раздел, обновлять roadmap. Редактируй только релевантные разделы, не переписывай весь файл.
3. Делай git commit после каждой значимой реализованной фичи (не после каждой мелкой правки/итерации баланса) с осмысленным сообщением на английском, описывающим, что изменилось.
4. Если задача - это баг-фикс, регресс или правка баланса на основе моего фидбека - коммить не обязательно каждый раз, но обязательно ПЕРЕД началом крупной новой фичи, чтобы можно было откатиться к последнему стабильному состоянию.
