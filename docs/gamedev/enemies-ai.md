# Враги и ИИ

← [База знаний](README.md)

## Роли врагов
Враг имеет смысл, только если **меняет поведение игрока**. Для каждого врага записать «вопрос»,
который он задаёт.
| Роль | Вопрос игроку | Пример |
|---|---|---|
| Мясо (fodder) | «Убей меня по пути», источник ресурсов | Зомби, импы; рой |
| Стрелок | «Не стой на месте» | Дальник |
| Танк | «Найди правильное оружие или слабое место» | Барон, манкубус |
| Рашер / фланкер | «Следи за спиной, держи дистанцию» | Пинки, охотник |
| Зона запрета | «Не ходи туда» | Турель, мины, огонь |
| Бомбист | «Убей до подхода или отойди» | Подрывник |
| Поддержка | «Убей меня первым» | Лекарь, баффер, призыватель |
| Нарушитель правил | «Перестрой привычную тактику» | Мародёр, щитоносец |

- **Мясо обязательно.** Без слабых врагов нет ощущения силы и нет ресурса для петли
  (см. [combat-weapons.md](combat-weapons.md)).
- **Силуэт** определяет роль: опасность читается по форме с 30 м и в бою. Цветовой код угрозы
  дублировать формой и звуком (дальтонизм).

## Телеграфы
- Каждая атака, наносящая заметный урон, предупреждает о себе: поза, вспышка, свечение, **звук**.
- Изменение должно начинаться **до** атаки, а не в момент выстрела.
- Длительность упреждения растёт с уроном: лёгкий выстрел ~0.3 с, тяжёлый удар 0.6–1.0 с.
- **Звуковой телеграф** обязателен для атак вне поля зрения: у каждого типа свой узнаваемый
  звук замаха.
- Единый язык телеграфов по игре: одинаковый цвет или форма значат одно и то же везде.
- Проверка честности: на повторе смерти видно, что игрок должен был сделать.

## Снаряды
- Бумер-шутеры предпочитают **видимые снаряды** хитскану: от них можно увернуться движением,
  и это поощряет скорость.
- Снаряд яркий, насыщенный, контрастный к окружению, со светом или следом. Скорость такая,
  чтобы направление читалось, но уклонение рывком/стрейфом было возможно (ориентир
  15–30 м/с; дальник VOIDKILL — 18 м/с).
- Хитскан у врага — только с явным телеграфом (лазерный прицел + задержка) и с пониженной
  точностью.
- Самонаведение слабое и с ограничением угла поворота, иначе уклонение невозможно.

## Токены атак (DOOM 2016)
- У каждого типа атаки (ближняя, дальняя, заряженная) — **ограниченный пул токенов**. Враг
  берёт токен перед атакой и возвращает после. Нет токена — нет атаки (враг маневрирует,
  занимает позицию).
- Враг на экране может **отобрать** токен у врага за экраном: игрок не видит отменённую атаку
  за спиной и получает урон от того, кого видит.
- **Размер пула — ручка сложности**: на высокой сложности враги кажутся агрессивнее.
- Враг не начинает новую атаку, пока не закончил текущую.
- Тот же принцип у Naughty Dog для ближнего боя в TLOU2.

## Восприятие и точность (DOOM 2016)
- **Точность врагов падает при высокой скорости игрока** и растёт, когда он стоит. Напрямую
  поощряет движение. Масштабируется сложностью.
- Позиционирование инвертировано относительно укрытий: ИИ ищет **открытые** точки рядом с
  укрытием, видимые игроку. Враги выходят на бой, а не прячутся.
- Дальние враги удерживают дистанцию, а не идут в упор.
- Нарастающая реакция на урон: дёрганье → сбой → оглушение (окно добивания). Отдельные оружия
  вызывают свои реакции.
- Ни один враг не начинает атаку во время добивания (игрок неуязвим в анимации).
- Головы и тела поворачиваются к игроку через IK — враг «смотрит», это читается как намерение.
- Межфракционные драки (infighting) по записи урона между типами.

## Энкаунтерный ИИ (Halo)
- «30 секунд веселья» (Jaime Griesemer): ядро игры — 30-секундный цикл, который повторяется
  в меняющемся контексте.
- Энкаунтер: **вход → план → исполнение**. ИИ поддерживает каждую фазу: даёт рассмотреть
  позиции, реагирует на план, красиво «ломается» под давлением (бегство, перегруппировка).
- Цель — **иллюзия** стратегического интеллекта, без читерства. Дизайн отвечает за горизонт
  ~3 минут, код — за ~30 секунд и мгновенные реакции.

## Архитектура ИИ
- Конечный автомат (FSM) для простых врагов, **иерархический** (HFSM) — когда состояния
  группируются (ближний бой / дальний бой / реакция). Дерево поведения — для сложной логики
  с приоритетами; для бумер-шутера обычно избыточно.
- Хук выхода из состояния гасит визуал и таймеры, но не меняет состояние (уже урок
  в `docs/lessons.md`).
- Каждое состояние имеет **таймаут** или условие выхода, иначе враг «залипает».

## ИИ при сотнях врагов
- **Распределение по кадрам**: восприятие, перепрокладка пути и выбор цели — раз в N мс со
  случайной фазой, а не в каждый кадр (VOIDKILL: обнаружение раз в 0.2 с).
- **LOD ИИ**: далёкие и невидимые враги обновляются реже, проще (без IK, без лучей видимости).
- **Путь** запрашивать по интервалу и при заметном смещении цели. Многие вызовы
  `NavigationAgent3D` пересчитывают путь целиком.
- **Избегание (RVO) дорогое**: включать только тем, кому нужно, сужать `avoidance_mask`.
- Физзапросы (лучи, шейпкасты) — главный расход: кэшировать результаты, не стрелять лучами
  каждый кадр с каждого врага.
- `Area3D` для «радиуса до игрока» — квадратичная цена в физике; проверка расстояния в коде
  дешевле (урок проекта, `CLAUDE.md` §3).
- Пул врагов вместо `instantiate`/`queue_free` на каждой волне, если спавн заметно дёргает кадр.

## Спавн
- Появление **с телеграфом** (эффект, звук), никогда — вплотную к игроку и в поле его прыжка.
- Спавн за спиной допустим для давления, но со звуком и с задержкой атаки.
- Волна начинается, когда игрок может её прочитать: первые враги видны с входа.

## Сложность
- DOOM Eternal: **способности врагов одинаковы на всех сложностях**, меняются частота тяжёлых
  атак и урон. Сложность меняет запас на ошибку, а не то, чему надо учиться. В DOOM 2016
  поведение менялось между сложностями — и учить приходилось «новый танец».
- Ручки: урон по игроку, размер пула токенов, частота тяжёлых атак, точность, скорость
  снарядов, количество врагов, ресурсы с убийств.

## Применительно к VOIDKILL
- Токенов атак нет. Со ~160 живыми врагами (бюджет из `docs/levels.md`) пул токенов —
  основной способ держать давление честным, не правя каждого врага.
- Точности от скорости игрока нет — естественная связка со столпом «скорость».
- Телеграфы в `docs/enemy-types.md` описаны визуально. Стоит проверить, у всех ли атак есть
  **звуковой** телеграф (сейчас звук процедурный и общий, `AudioManager` двухмерный).
