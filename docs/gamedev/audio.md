# Звук и музыка

← [База знаний](README.md)

## Звук — половина ощущения
В шутере звук передаёт попадание, угрозу вне поля зрения, скорость и состояние ресурсов. Если
картинка и звук спорят, игрок верит звуку. Звук, приходящий позже картинки на 1–2 кадра,
ощущается как «ватный» отклик.

## Слои выстрела
| Слой | Роль |
|---|---|
| Транзиент (атака) | Резкий щелчок в начале. Без него выстрел глухой |
| Тело (close) | Характер оружия, весь диапазон. Если слой один — то этот |
| Саб / панч | Низкочастотный вес, удар в грудь |
| Механика | Затвор, барабан, поршень: материал и состояние оружия |
| Хвост | Затухание и пространство. Сообщает размер помещения и дистанцию |

- Слои хранить отдельно: так легко делать варианты и правки микса.
- Типичная обработка: эквалайзер, сатурация, шейпер транзиентов, клиппер.
- Для врагов — отдельный **дальний** вариант: по нему слышно, откуда и как далеко стреляют.
- Тот же принцип — для ударов, взрывов, шагов: транзиент + тело + хвост.

## Против «пулемётного эффекта»
- 3–5 **вариантов** каждого частого звука, выбор без повтора подряд (round-robin).
- Случайная высота ±3–8% и громкость ±1–2 дБ на каждое воспроизведение.
- В Godot: `AudioStreamRandomizer` (варианты, `random_pitch`, `random_volume_offset_db`, режим
  без повтора).

## Микс и приоритеты
Порядок важности для бумер-шутера:
1. Телеграфы атак врагов (особенно вне экрана).
2. Собственное оружие и попадания игрока.
3. Урон по игроку, низкое здоровье, ресурсы (BPM, заряды рывка).
4. Смерти врагов, кровь.
5. Шаги врагов, окружение.
6. Музыка.

- **Лимит голосов** на тип звука (3–6 одинаковых одновременно). Новый звук гасит самый
  старый или тихий, а не накладывается. Сто попаданий роя за кадр — это шум, а не информация.
- **Даккинг**: важные события временно приглушают музыку и фон (компрессор с сайдчейном на
  шине музыки).
- **Лимитер** на мастере — чтобы взрыв поверх стрельбы не клиппировал.
- Разные звуки занимают разные частоты: телеграф врага не в той же полосе, что выстрел игрока.

## Позиционный звук
- Угрозы — `AudioStreamPlayer3D`: направление и дистанция слышны. Звуки самого игрока и UI — 2D.
- `max_distance` отсекает далёкие источники от микширования (экономия CPU).
- `max_polyphony` по умолчанию **1**: повторный звук обрывает предыдущий. Для накладывающихся
  звуков поднять.
- Скрытый узел звук **не глушит** — нужно `volume_db` около −80…−100 или `stop()`.
- Доступность: важные направленные звуки дублируются визуально (индикатор направления урона).

## Шины (Godot)
```
Master (HardLimiter)
├── Music (Compressor с sidechain от SFX)
├── SFX
│   ├── Player
│   ├── Enemies
│   └── UI
└── Ambience
```
- Отдельные ползунки громкости: общая, музыка, эффекты (минимум по доступности). Значение
  ползунка 0..1 переводить через `linear_to_db()`.
- Раскладка шин — ресурс `default_bus_layout.tres`.

## Адаптивная музыка
- **Вертикальные слои**: одна композиция из синхронных стемов, интенсивность добавляет или
  убирает слои (ударные, гитары, синт). Плавно, без швов.
- **Горизонтальная пересборка**: трек нарезан на секции, переходы между ними по границам тактов
  в зависимости от состояния (исследование → бой → пик → затишье).
- DOOM 2016 (Mick Gordon, GDC 2017): треки порезаны на мелкие части, которые код выбирает по
  происходящему, поэтому музыка почти не повторяется.
- В Godot 4.3+ есть встроенное:
  - `AudioStreamSynchronized` — синхронные стемы с отдельной громкостью (вертикальные слои);
  - `AudioStreamInteractive` — клипы с переходами по такту и правилам (горизонталь);
  - `AudioStreamPlaylist` — последовательность треков.

## Процедурный звук
- Удобен для прототипа и отдельных эффектов (сердцебиение, ветер на скорости, гул), но
  настоящие записанные звуки богаче. Типичный путь — записи/библиотеки для ударных событий,
  процедурное — для непрерывных параметрических (скорость, BPM).
- `AudioStreamGenerator` требует заполнять буфер из скрипта; на каждый звук это дороже, чем
  проиграть готовый `AudioStreamWAV`. Генерировать один раз при загрузке, а не при каждом проигрывании.

## Применительно к VOIDKILL
- `scripts/audio_manager.gd` генерирует ~25 процедурных звуков, все через 2D-плееры на шине
  `Master`, со случайной высотой у частых звуков и лимитом 4 копии на звук. Позиционного звука,
  отдельных шин и музыки нет. По roadmap п.24 — замена на настоящие.
- BPM-тиры (CALM / PUMPING / SURGING / OVERDRIVE) естественно ложатся на **вертикальные слои**
  `AudioStreamSynchronized`: тир включает слой. Привязка темпа музыки к BPM отклонена в
  `docs/bpm.md` только как ритм-механика, а интенсивность музыки от тира с этим решением не спорит.
- Звук сердцебиения, учащающийся с BPM, в `docs/bpm.md` отмечен как запланированный.
